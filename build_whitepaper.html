第1章 生成范式与模型地图

拿到视频或世界模型做推理优化，第一步是确认每次前向更新哪些生成位置。整段视频共同去噪、离散码逐个追加、连续 latent 按 chunk 生成，对应不同的 Query 长度、历史状态和并行机会。同一个模型系列下，不同 checkpoint 和任务入口走的计算图也可能不同，分析需要落到具体推理路径上。

三种生成方式

全序列扩散（双向 Attention）

FLUX.1、Wan2.1、HunyuanVideo、CogVideoX 等模型的常规生成路径在每个去噪步更新整段 latent。对没有 padding 或其他限制的 dense self-attention，“全部位置可见”指布尔连接 mask 全 true，或加性 mask 全 0；Attention 权重仍由 $\operatorname{softmax}(QK^\top/\sqrt d)$ 决定。

常规实现会随当前 latent 重新计算其 KV，不直接复用上一去噪步的动态 KV；条件编码、scheduler 的多步历史和特征缓存各自独立维护。只有当各步的张量形状、分支和执行路径都一致时，总工作量才可近似为调用次数乘以单次 FLOPs。长序列能提供充足的并行工作，但是否跑满 Tensor Core 还取决于矩阵几何、内存布局和所选 Kernel。

离散 Token 自回归（Discrete Token-AR）

LlamaGen 按 token 顺序生成离散码；VAR 则按尺度生成网格，尺度之间因果、同尺度内并行。Mask 与单次 query 长度随生成单位而变化。VAR 原生实现按 scale ID 构造训练 mask，并在推理时逐尺度更新 KV。TiTok 是一种 tokenizer，其原始工作搭配 MaskGIT 式生成，不归入普通因果 AR。

Prefill 并行处理给定前缀，前缀长度由输入决定。采用 KV cache 时，Decode 只计算当前生成单位：batch 很小、每次 query 为 1 时，线性投影退化为 GEMV 形状，attention 也容易受限于 KV 读取带宽与并行度不足；VAR 的 query 数随尺度增长，后期大尺度网格更接近矩阵乘几何。离散码预测通常输出 logits 并采样，不在每个 token 上执行迭代去噪。

连续因果分块扩散（Continuous Causal Chunk Diffusion）

SolarWM-H3、CausVid 和 Self Forcing 等路线按时间块生成连续 latent，当前块内部仍执行多步去噪求解。块内可采用双向 attention，跨块依赖已经生成的历史；块大小、历史噪声水平、可见窗口与 KV 保存位置由各自训练和实现规定。

在“先去噪、再提交 clean 上下文”的实现中，两类前向承担不同职责：最后一次去噪使用的是更新前的带噪 latent，提交历史则使用最终预测的 clean latent。Self Forcing 官方推理同样包含去噪后的 context 更新。两类调用的计数与成本拆解见第6章。

第2章 从输入到输出的执行图与工作量

一次请求不仅是若干次 Attention。条件编码、patch 投影、每层 QKV/MLP、归一化、采样更新、状态刷新和解码构成完整执行图。本章先把几何和工作量列清，后续各章再决定改变哪一项。

从 latent 到时空 Token

Patchify 后有多少 Token

视频生成模型通常在 3D-VAE 的低维潜空间（Latent Space）中进行特征变换。 设潜空间输入张量为 $Z \in \mathbb{R}^{B \times C \times T \times H \times W}$，其中：

  • $B$ 为 Batch Size；
  • $C$ 为潜变量通道数，由具体 codec 定义；
  • $T$ 为经 VAE 时间压缩后的时序长度；
  • $H, W$ 为经 VAE 空间压缩后的高度和宽度。

采用无重叠的切块尺寸 $(p_t,p_h,p_w)$，且三个维度均可整除时： $$N_{\text{video}} = \frac{T}{p_t} \times \frac{H}{p_h} \times \frac{W}{p_w}$$ 尺寸无法整除时，查看实现采用 padding、裁剪还是拒绝输入。无 padding、stride 等于 kernel 的卷积会向下取整，边缘覆盖范围也随之变化。像素帧数到 latent 帧数也要查 codec，因果 codec 可能有首帧偏置。 映射后的张量形状为 $X_{\text{video}} \in \mathbb{R}^{B \times N_{\text{video}} \times D}$，其中 $D$ 为 Transformer 隐藏层维度（Hidden Dimension）。

条件接入方式与 Packed 布局

“模型同时接收文本与视频”不表示它们共享同一个 self-attention 序列。joint attention 会拼接参与交互的 token；cross-attention 则以视频为 query、文本等条件为 KV。例如Wan2.1 的 WanT2VCrossAttention分别投影 x 与 context。时间、类别或相机条件还可能通过 modulation 或位置变换接入，不一定占用额外 token。

对于确实使用 joint attention 的实现，一个样本的逻辑序列可以写为： $$X_{\text{total}} = [X_{\text{text}} \,\|\, X_{\text{ref}} \,\|\, X_{\text{video}} \,\|\, X_{\text{audio}}] \in \mathbb{R}^{1 \times N_{\text{total}} \times D}$$ 其中 $N_{\text{total}}=\sum_m N_m$。这里仅示意逻辑布局，具体模态顺序由模型定义。逻辑拼接与跨样本 packing 也要分开：后者才是在支持变长的 kernel 中省去样本间 padding 的一种方式。

变长 Attention（varlen）接口中的 cu_seqlens 标记独立样本的序列边界。同一样本内需要相互注意的模态应放在同一序列中，模态边界另行记录，允许的交互关系由 Attention Mask 指定：

单个多模态样本: cu_seqlens = [0, N_total]
两个独立样本:   cu_seqlens = [0, N_sample0, N_sample0 + N_sample1]

若将 text/ref/video 各段作为 cu_seqlens 中的独立序列，这些段之间就不再计算 Attention。跨样本 packing 可以减少 padding 开销，仍需核验所选 Kernel 对数据布局和 Mask 的支持。

序列长度对注意力的影响

考虑一个几何算例，假设输入 1920×1080、120 帧，codec 恰按时间 4 倍、空间 8 倍缩小，得到 $30\times135\times240$ latent。若 patch 为 $1\times2\times2$，高度 135 不能整除 2。假设实现允许将 latent 高度补到 136，则： $$N_{\text{video}}=30\times68\times120=244,800$$ 在 batch 为 1、32 个 head、每元素 2 bytes 时，仅一份完整 score 矩阵就需要： $$B H_{\text{heads}}N^2b=1\times32\times244,800^2\times2\approx3.84\text{ TB}$$ 其中 $1\text{ TB}=10^{12}\text{ bytes}$（全文约定十进制单位 MB、GB、TB 分别表示 $10^6,10^9,10^{12}\text{ bytes}$，二进制单位 KiB、MiB、GiB 分别表示 $2^{10},2^{20},2^{30}\text{ bytes}$），容量未计其他张量。这个几何算例不对应某个模型的原生输入配置，但足以说明保存完整注意力分数矩阵的显存成本。采用分块 Attention 可以避免这份完整中间矩阵，无须为此强制引入多卡序列切分；Dense Attention 的二次方计算量仍然存在。

DiT Block 中的主要路径

flowchart TD X["hidden states [B,N,D]"] --> N["Norm与时间/条件调制"] N --> Q["QKV投影与QK Norm / RoPE"] Q --> A["Attention Core"] A --> O["输出投影与残差"] O --> M["Norm / 调制 / MLP / 残差"] M --> Y["下一层 [B,N,D]"]

这是常见路径示意，具体模型可增加 cross-attention 或多模态分支。实际 Kernel Launch 数要沿 trace 统计：view 可能只改元数据，一次库调用也可能发射多个 Kernel。残差、Norm 与位置变换的 FLOPs 较少，但中间张量和 launch 仍可能进入关键路径。

单层工作量与显存流量

投影、Attention 与 MLP 的工作量

以一个标准 DiT Block 为例，设定隐藏层维度为 $D$、序列长度为 $N$、注意力头数为 $H$、每个 Head 维度为 $d = D/H$：

浮点运算量（FLOPs，按单 Batch 计）

  • QKV 投影：$W_{qkv} \in \mathbb{R}^{D \times 3D}$，计算量为 $2 \times N \times D \times 3D = 6 N D^2$；
  • Attention Core：
    • $QK^T$ 矩阵乘：$2 \times N \times N \times D = 2 N^2 D$；
    • $\text{Softmax}(S) \cdot V$ 矩阵乘：$2 \times N \times N \times D = 2 N^2 D$；
    • Attention Core 合计：$4 N^2 D$；
  • 输出投影 Out Linear：$W_o \in \mathbb{R}^{D \times D}$，计算量为 $2 \times N \times D \times D = 2 N D^2$；

  • 前馈网络（MLP）：

    • 标准 GELU MLP（2 层 Linear，隐层维度 $4D$）： $$\text{FLOPs}_{\text{GELU}} = 2 \times (2 \times N \times D \times 4D) = 16 N D^2$$

    • SwiGLU MLP（3 层 Linear，隐层维度通常取 $\frac{8}{3}D$）： $$\text{FLOPs}_{\text{SwiGLU}} = 3 \times \left(2 \times N \times D \times \frac{8}{3}D\right) = 16 N D^2$$

    • 若 SwiGLU 隐层维度按 $4D$ 配置，则计算量扩展为 $24 N D^2$。

单 Block 总运算量（以 $16ND^2$ MLP 计）： $$\text{FLOPs}_{\text{block}} = 24 N D^2 + 4 N^2 D$$

AR-chunk 中应将 query 长度与 KV 长度分开。设当前块有 $M$ 个 query、可见 KV 共 $L_{\text{KV}}$ 个 token，在上述 MHA 宽度假设下，attention core 为 $4BM L_{\text{KV}}D$ FLOPs。当前块的 QKV 投影、输出投影与 MLP 约为 $24BM D^2$；已缓存的历史 KV 不重复投影，新增条件分支另算。连续 AR 的一个 chunk 通常包含千余至数千个 query；此时投影仍是矩阵乘，应代入实际 $M$，而不是按单 Token Decode 的 GEMV 估算。

设备显存流量（Device-memory traffic）

显存流量取决于 Attention 的具体底层实现方式：

  • 实现方式 A：显式保存注意力矩阵。注意力分数（score）是 $QK^\top/\sqrt d$，概率矩阵（probability）是其逐行 softmax 的结果；每个 head 的两种矩阵形状均为 [N,N]。若将其中任一种完整写入显存，设 head 数为 $H$、每元素占 $b$ bytes，中间矩阵相关流量随 $HN^2b$ 增长；具体读写次数取决于 softmax 和算子融合方式。前述 MLP 假设下，投影与 MLP 共含 $12D^2$ 个权重元素；一次权重读取或一次注意力矩阵读写都不代表完整 Block 的实际流量。

  • 实现方式 B：FlashAttention 分块计算。分块与 online softmax 避免将完整的 $N\times N$ 分数或概率矩阵写入显存，辅助存储随序列长度线性增长，但 KV 可能被不同 query tile 重复读取。HBM 流量还要结合 tile 和 KV 重读次数分析。

在两级存储分析中，令 $d=D/H$ 为单 head 维度、$M$ 为可用快存容量（以元素计），单 head attention 的 IO 含 $Nd+N^2d^2/M$ 量级项；实际 L2 复用、tile 和 kernel 还会改变流量。见FlashAttention 原论文与IO 复杂度分析。算术强度需按实际流量计算，再用硬件计数器判断限制来自计算还是带宽。

Wan2.2：沿原生入口核对一次请求

固定源码依次编码正、负文本条件，准备噪声和 scheduler 时间表，选择当前噪声阶段的主干，再分别执行 conditional 与 unconditional 前向，组合预测后调用 scheduler 更新 latent。最后在输出 rank 执行 VAE decode。只改变 guidance 数值时，这两次主干调用仍会执行；省去分支需要修改路径或采用匹配的蒸馏模型。

设 scheduler 实际迭代 $S$ 次，且每次都走上述两次 model 调用，则源码路径的主干调用数为 $2S$。两份 expert 各承担多少次取决于时间表与 boundary；每步只执行被选中的一份 expert。这个源码计数用于明确工作量，实际延迟再测。改变 scheduler、分支合批或蒸馏入口后应重新计数。

AR：每块去噪与状态提交分开

设一个 chunk 有 $C$ 个 latent 时间片，每片经 patchify 后有 $P$ 个视频 Token，则当前视频 query 长度为 $M=CP$。历史窗口如果保留 $K$ 个完整 chunk，视频历史长度为 $KCP$；reference、音频和其他条件是否进入同一 Attention 序列，需按模型分别计数。

每块执行 $S$ 次去噪、$R$ 次上下文更新时，主干调用数为 $S+R$。上下文更新还包含状态写入，成本未必与去噪相同。先在日志中区分 denoise 与 commit，再统计每层调用及其 Shape；第12章沿状态生命周期解释为什么两者需要分开。

第3章 GPU 执行与性能约束

把 GPU 简化为一个峰值 TFLOPS 数字，会掩盖大部分工程瓶颈。同一 DiT 层既有大 GEMM，也有归约、重排、短 Kernel 和数据拷贝；它们对 SM、存储层次和调度的需求截然不同。定位性能问题时，先区分受限于算力、带宽还是调度空档，再决定是增加并行度还是减少数据搬运。

从线程到 Tile

CUDA Kernel 把工作划分成 thread blocks；block 内线程以 Warp 为执行单位。一个 SM 能同时驻留多少 block/Warp 受线程数、寄存器、shared memory 及架构上限共同限制。Occupancy 反映活跃 Warp 相对架构上限的比例；更多 Warp 有助于掩盖访存等待，但也可能因寄存器压力限制单个 block 的 tile 规模。

GEMM 和 Attention Kernel 通常按 Tile 消费张量。假设输出矩阵为 $[M,N]$、输出 Tile 为 $[B_M,B_N]$，未考虑 split-K 时输出任务块数为：

$$\mathrm{tiles}_M=\left\lceil\frac{M}{B_M}\right\rceil,\qquad \mathrm{tiles}_N=\left\lceil\frac{N}{B_N}\right\rceil,\qquad \mathrm{output\_tiles}=\mathrm{tiles}_M\times\mathrm{tiles}_N$$

当 $M$ 很小，即使 $K$ 和 $N$ 很大，输出 Tile 数也可能不足以铺满整卡 SM。相反，增大 Tile 能提高片上数据复用，却会消耗更多寄存器和 shared memory；在长视频序列上高效的 Tile 未必适合短 chunk。分析时还需兼顾末尾不足一个 Tile 的边界浪费与 Wave 量化效应。

Tensor Core 执行的是满足特定指令与布局约束的矩阵运算。FP8 张量必须由匹配的 Kernel 消费才能走 FP8 Tensor Core；若 Shape、对齐或架构不匹配，底层可能回退到高精度路径。核对性能规格时，需区分 Dense 峰值与 2:4 结构化稀疏峰值，常规稠密算子以非稀疏峰值为参照。

存储层次与布局

权重和激活主要驻留设备显存（HBM/GDDR），数据经 L2/L1 cache 进入 SM，Kernel 可利用 shared memory 在 block 内复用数据，再送入寄存器做矩阵乘。L2 命中率直接决定落到显存颗粒上的真实流量；理论最小读写字节数给出下界，实际带宽消耗以硬件计数器为准。

例如 Q 的逻辑 Shape 同为 [B,H,N,d]，连续的 $d$ 维和连续的 $N$ 维对应不同的物理地址步幅（stride）。transpose 通常只创建带新 stride 的 view；若下游算子要求连续布局，隐式或显式的 contiguous() 就会触发真实内存拷贝。为了省一次转置而让主计算 Kernel 以低效 stride 访存，往往得不偿失，因此布局选择需要把生产者、转换和消费者放在同一段区间内衡量。

Coalesced access 关注同一个 Warp 的访存地址能否合并为尽量少的内存事务。逐 token 随机 gather、非连续 head 排列和细碎拷贝都会拉低有效带宽；按整块组织的稀疏模式更容易保持连续读取。执行和访存细节可参见CUDA Best Practices。

Roofline 提供约束，不直接诊断整模型

设一个算子包含 $F$ 次浮点操作、实际穿过目标存储层的字节数为 $B$，硬件在对应精度下的有效计算吞吐为 $P$、有效带宽为 $\mathrm{BW}$，则理想重叠下的耗时下界为：

$$I=\frac{F}{B}\quad(\mathrm{FLOP/byte}),\qquad T_{\mathrm{compute}}\ge\frac{F}{P},\qquad T_{\mathrm{memory}}\ge\frac{B}{\mathrm{BW}}$$ $$T_{\mathrm{kernel}}\ge\max(T_{\mathrm{compute}},T_{\mathrm{memory}})$$

这个下界不包含 Kernel Launch、依赖等待、Tile 尾部浪费和非矩阵指令瓶颈。DiT 主干不总是 Compute-bound，AR Decode 也不总是 Memory-bound：batch、query/KV 长度、dtype 和布局都会改变算术强度。

以矩阵乘 X[M,K] × W[K,N] 为例，乘加按 2 FLOPs 计，输入输出每元素占 $b$ bytes 且理想情况下只读写一次：

$$F=2MKN,\qquad B_{\min}=b(MK+KN+MN),\qquad I_{\mathrm{ideal}}=\frac{2MKN}{b(MK+KN+MN)}$$

$M=1$ 时，读取权重 $W$ 的字节无法在多个 token 间摊销；$M$ 增大后权重复用率随之提升。连续 AR-chunk 的单块 token 数 $M$ 往往在千余至数千量级，其线性投影完全属于矩阵乘几何，而不是单 token Decode 的 GEMV。矩阵乘分块与带宽背景见 NVIDIA GEMM 指南。

Kernel Launch 与依赖

CPU 可以异步向 GPU 队列提交工作。短 Kernel 密集串联时，Host 发射、Python 分支或隐式同步容易让 GPU 出现断流等待；而当单个大 Kernel 已经吃满设备时，单纯削减 launch 次数带来的收益就很有限。CUDA Graph 主要省去重复发射的 Host 开销，算子融合则重在省去中间结果的显存读写。

多 Stream 允许表达无依赖的并发工作，但不会凭空增加 SM、显存带宽或 DMA 引擎。如果两个大 Kernel 争抢同一硬件资源，并发执行反而可能拉长各自耗时。只有结合时间线（trace）观察实际重叠区间与关键路径变化，才能确认多流并发是否真正奏效。

架构差异如何进入实验

Hopper 与不同 Blackwell 产品的算子支持路径存在显著差异。面向 SM90（如 H100/H800）调优的 Kernel 不会自动适配 SM120（如 RTX 5090），同一架构代号下的不同芯片在共享内存配额、互联带宽和可用指令上也有区别。从“编译通过、算子可调、数值正确”到“单算子提速、整模质量达标”，每一步都是独立的工程门槛，实验记录需注明物理 GPU 型号、Compute Capability、工具链版本与输入几何。

第4章 状态、显存与数据生命周期

四类缓存有不同的有效性条件

推理系统里常见的四类缓存具有截然不同的失效边界：跨步特征缓存复用近似的网络输出或残差，依赖采样轨迹、时间步与误差阈值；AR 历史 KV 保存已生成上下文，受提交时机、位置编码与滑动窗口协议约束；条件侧缓存保存固定文本等条件投影，随层和 expert 权重区分；跨请求前缀复用则要求模型权重、输入条件与位置语义完全一致。当前 chunk 在去噪迭代中动态更新的 Q/K/V 与已经提交归档的历史 KV 属于不同生命周期，不能混用同一块缓冲。

KV 容量先按表示形式计算

设历史窗口保留 $K$ 个等长 chunk，每个 chunk 的 K 和 V 形状均为 [B, N, H_kv, d]，共 $L$ 层，每元素占 $b$ bytes。仅计未压缩 K/V 张量本身的载荷：

$$M_{\mathrm{chunk,layer}}=2BNH_{\mathrm{kv}}d\,b,\qquad M_{\mathrm{history}}=KLM_{\mathrm{chunk,layer}}=2KLBNH_{\mathrm{kv}}d\,b$$

其中 $H_{\mathrm{kv}}$ 为 KV head 数（采用 GQA 时需与 query head 数区分）。若采用量化缓存，还需计入 scale、对齐 padding 与页表索引；若采用静态分页池，则需按预分配的总页槽位数核算常驻显存。

如何排查增长与碎片

在固定窗口配置下连续运行多轮填窗、淘汰和 reset，在相同代码位置采样 allocated、reserved、活跃 Python 对象与在途缓冲字节数。未清理的输出列表、因 Shape 变化触发的 CUDA Graph 重复捕获、残留闭包引用以及下游消费队列积压，都会表现为显存随轮次单调爬升。若 reserved 远高于 allocated 且剩余空闲显存充足却仍报分配失败，则可借助分配器快照（memory snapshot）定位块碎片。

第5章 性能分析与可复现实验

离线单视频延迟、多请求吞吐、首帧与稳态 chunk 间隔会导向不同方案。先确定目标和交付终点，用不插桩的原生入口建立参考，再用短 profile 解释成本。本章集中定义计时、容量和质量原则；各章的合成实验按附录 A、C 给出的硬件、Shape、样本完整性和范围阅读。

Wall time 覆盖约定的 Host 和设备完成边界。CUDA Event 测量指定 Stream 的时间跨度，可能包含等待；Profiler 累计 device 时间可以跨 Stream、跨 GPU 重叠。报告中应分别命名。完整 E2E 还要写明终点是 latent、首份可播放帧、编码文件，还是客户端消费完成。

从请求缩小到一个成本项

先按条件编码、DiT、历史更新与搬运、decoder、编码及交付划分阶段。DiT 内再查看 Linear、Attention、Norm/调制、布局转换和通信。记录 Shape、stride、dtype、调用数和实际 backend，再只改变一个因素。

配对基准与环境漂移

A/B/A 依次运行参考 A1、候选 B、参考 A2。固定权重、输入、初始噪声、采样配置、硬件和计时范围，保留各臂的 warmup 与全部热样本。参考复测可以暴露背景负载、频率和温度变化，但三臂顺序本身不消除这些干扰。

以首轮基线 $T_{A1}$ 为分母计算前后漂移。结果为正，说明末轮基线 $T_{A2}$ 变慢，可能出现了降频或背景干扰：

$$\mathrm{Drift}_{A2/A1}=\left(\frac{T_{A2}}{T_{A1}}-1\right)\times100\%$$

$$\mathrm{Speedup}=\frac{(T_{A1}+T_{A2})/2}{T_B}$$

数值等价与近似误差

对预期保持语义的修改，检查 dtype、比较位置、max absolute error、Relative L2、有限性与状态更新。浮点归约次序变化也可能产生微小差异，因此容差要按实现预设。只有逐位相同才记 bitwise。

$$\text{Rel-L2}=\frac{\|Z_{\mathrm{candidate}}-Z_{\mathrm{reference}}\|_2}{\|Z_{\mathrm{reference}}\|_2}$$

零范数分母单独处理。对蒸馏学生、跨步缓存或量化等近似方法，这个量可定位误差从何处开始增长，阈值需与方法和任务一起校准。它不应成为感知评估之前的一道通用淘汰线：模型改变、轨迹分叉后，较大的 latent 距离可能仍对应可接受的视频。

PSNR、SSIM 和逐帧 LPIPS 适合有空间对应关系的配对输出。蒸馏学生生成的运动或构图可以与 teacher 不同，此时逐像素比较会惩罚有效的生成差异。应同时采用提示词/条件保持、细节、运动幅度、时序一致性及人工配对评估；在固定输入集上报告质量分布和失败比例。

时序重投影误差

令 $p=(x,y)$ 为第 $t+1$ 帧的位置，后向光流 $F_{t+1\to t}(p)$ 指向第 $t$ 帧的对应位置，以双线性采样重建：

$$\hat I_{t+1}(p)=I_t\!\left(p+F_{t+1\to t}(p)\right)$$

令 $m(p)\in\{0,1\}$ 保留可见且采样有效的位置，$C$ 为颜色通道数，有效区域的平均绝对误差为：

$$E_{\mathrm{temp}}=\frac{\sum_p m(p)\,\|I_{t+1}(p)-\hat I_{t+1}(p)\|_1}{C\sum_p m(p)}$$

固定光流估计器、像素值范围、遮挡规则和聚合方式；空 mask 单独报告。使用 grid_sample 时将源像素坐标转成归一化网格，并固定 align_corners。接口定义采用输出位置到输入坐标的映射。

这个残差用于诊断运动补偿后的不一致。过度静止或模糊也会得到小残差，因此还要观察实际运动和细节。AR 应按 chunk 位置统计，并覆盖窗口填满、多次淘汰和长期运行；基线自身的退化也作为质量问题记录。

联合 AV 任务另外测音频内容、音质、PTS 连续性和语义同步；纯视频将音频项记 N/A。时间戳连续、媒体可解码和感知质量分别验收。

第6章 减少网络求值：求解器、少步、CFG 与蒸馏

NFE（Number of Function Evaluations）统计被计数函数的求值次数。论文可能计 ODE 右端函数，工程日志则可能计实际 model call；有 CFG 时两者未必相等。把正负分支拼成 $2B$ 批大小后，虽然只发起一次 model() 调用，仍要执行两份分支工作。因此实验应同时报告 scheduler 更新数、denoise model calls、每次调用的 batch/CFG 分支和额外 refresh；统计工作量时，分支倍数只计一次。

在相同积分区间减少步数，会增大部分步长 $\Delta t$。截断误差、网络预测误差与引导强度共同影响采样结果；更少的步数并不自动保留质量。本章分别讨论高阶求解器、时间网格重映射和少步蒸馏。

求解器怎样减少求值

概率流 ODE 与截断误差

Song 等人的 SDE 框架在相应正则和 score 假设下，构造与扩散 SDE 具有相同时间边缘分布的概率流 ODE。对漂移 $f(x_t,t)$ 与仅依赖时间的标量扩散系数 $g(t)$，其形式为： $$\mathrm{d}x_t = \left[ f(x_t, t) - \frac{1}{2} g(t)^2 \nabla_{x_t} \log p_t(x_t) \right] \mathrm{d}t$$ 对满足相应光滑性条件的确定性 ODE，一阶 Euler 法的局部截断误差为 $\mathcal{O}(\Delta t^2)$，全局误差为 $\mathcal{O}(\Delta t)$。随机 SDE 的 Euler-Maruyama 需另行分析；采样步数取决于速度场、调度器与质量目标。

DPM-Solver++利用扩散 ODE 的半线性结构，解析处理线性项，对数据预测网络对应的积分项构造高阶近似。UniPC将 predictor 与 corrector 统一起来，并利用已有预测提高阶数；其 corrector 不要求额外的模型求值。多步法复用历史预测，因此应沿实际算法统计求值次数；启动阶段、历史长度和最后一步处理仍要看实现。

在相应光滑性、稳定性和启动条件下，二阶法的局部误差可为 $\mathcal{O}(\Delta t^3)$、全局误差为 $\mathcal{O}(\Delta t^2)$。误差阶数不直接保证生成质量，仍须在同一模型与调度设置下配对验证。

流匹配（Flow Matching）与速度场

Flow Matching 通过回归给定概率路径的速度场来训练生成模型，允许多种路径，也包含 diffusion 路径。本节以 FLUX.1、Wan2.1、SD3 等模型常用的直线条件路径为例，说明速度场与采样方向。原论文§4

速度场定义

取噪声先验 $p_1 = \mathcal{N}(0, I)$ 与真实数据分布 $p_0$，直线条件路径写作： $$x_t = (1 - t) x_0 + t x_1, \quad t \in [0, 1]$$ 对一对固定端点，其条件速度目标为： $$u_t(x_t\mid x_0,x_1)=\frac{\mathrm{d}x_t}{\mathrm{d}t}=x_1-x_0$$ 但网络只看到 $x_t,t,c$，并不知道这对端点。在平方误差目标下，它拟合的是条件期望： $$v_t(x,c)=\mathbb{E}[x_1-x_0\mid x_t=x,c]$$ 不同样本路径可能经过同一位置。条件路径是直线，不代表边缘速度场的积分轨迹也是直线。本节取 $t=1$ 为噪声端，采样从 1 向 0 积分；若模型用相反时间方向，速度符号也要随之变换。依据见Flow Matching 原论文§3。

时间网格的 Shift

固定求值预算时，时间网格决定把计算花在哪些噪声区间。下面的 shift 映射可见于Wan2.1 的 Flow UniPC 实现，但不是所有 scheduler 共用的公式： $$t_{\text{shifted}} = \frac{s \cdot t}{1 + (s - 1) \cdot t}$$ 当 $s>1$ 时，内部网格点被映射到更大的 $t$，端点 0 和 1 不变。在本节噪声端为 1 的约定下，时间点更偏向高噪声区域。位移并未减少 model calls，也不保证轨迹更直。参数与分辨率之间没有可通用套用的缩放律，应沿用 checkpoint 的训练/验证配置；改变 shift 属于需要配对质量验证的采样改动。

连续时间一致性模型（sCM）

一致性映射的理想目标是让同一概率流轨迹上的状态指向同一数据端点。省略条件，并用本节的 0/1 端点记号，可示意为： $$f_\theta(x_t, t) = f_\theta(x_{t'}, t') = x_0$$

实际模型通过训练近似这个目标，不会对任意样本严格满足等式。一步推理直接从噪声预测数据，多步采样则按匹配的加噪与预测协议校正。sCM 使用自己的 TrigFlow 参数化，上式仅示意一致性约束，完整时间坐标和损失见sCM 原论文。

分布匹配蒸馏

原始 DMD2 论文提出改进分布匹配蒸馏的训练方法，并支持经匹配训练的多步采样；具体视频 checkpoint 的目标、任务和调度以对应模型卡及源码为准。

DMD2 用 teacher 的 real score 与学习到的 fake score 估计分布匹配梯度，采用双时间尺度更新改善 fake critic 估计，同时用真实数据的 GAN 监督补充 teacher score，并移除先前 DMD 所需的配对回归损失。

部署时，学生的时间表、shift、引导及步数应匹配其训练和验证配置。支持多步的 checkpoint 按已验证入口运行，调整步数后重新评估质量。

CFG 单分支蒸馏与动态引导

Classifier-Free Guidance（CFG）通过显式组合有条件预测与无条件预测强化提示词相关性： $$v_{\text{guided}} = v(x_t, t, \emptyset) + w \cdot \left[ v(x_t, t, c) - v(x_t, t, \emptyset) \right]$$ 其中 $w$ 为引导系数。实际执行双分支时，可以分开前向或打包 batch；相对等成本单分支的求值工作增加，具体调用数、wall time 与峰值显存按原生实现记录。

引导蒸馏（Guided Distillation）

一种实现是把 $w$ 编码为 guidance condition，再让学生拟合 teacher 的组合预测。下面只是回归目标示意；guidance 如何注入、是否支持可变 $w$，按具体 checkpoint 的接口核对： $$\mathcal{L}_{\text{CFG}} = \mathbb{E} \left\| v_{\text{student}}(x_t, t, c, w) - v_{\text{guided}}^{\text{teacher}}(x_t, t, c, \emptyset, w) \right\|_2^2$$

  • 推理收益：若 checkpoint 已将引导行为蒸馏进单分支，并按其接口传入所需的 guidance 条件，可省去外部双分支组合。等成本分支求值数可减半；wall time 与峰值显存不保证减半；
  • 接入时检查：检查权重、guidance embedding 与原生调用协议。直接在未蒸馏模型上设 cfg_scale=1.0 会改变引导行为，需要重新评估提示词保持和画质。

单分支动态早退候选（Negative Early-Exit）

可以研究在部分去噪步关闭无条件分支，但这改变 CFG 计算，属于需质量验收的近似候选；APG 等方法则需要按各自的引导公式分析。

  • 示例前 6 步：保留双分支，共 12 次分支求值；
  • 示例后 14 步：令 $w=1$，只计算条件分支，共 14 次求值。

20 步合计 $12+14=26$ 次分支求值，而全程双分支为 40 次，分支求值工作少 35%。这只是等成本分支的算术示例，非实际 model call 数、系统耗时或 PSNR/CLIP 实测；分支打包、调度开销与质量差异应另测。

Wan2.2：把步数还原为实际工作

在固定 T2V 入口中，UniPC 和 DPM++ 分别构造自己的时间表；循环中每个时间点选一个 expert，并执行两次条件分支前向。令高噪声区间有 $S_h$ 个时间点、低噪声区间有 $S_l$ 个时间点，则该路径调用数为 $2(S_h+S_l)$，由两个 expert 承担 $2S_h$ 和 $2S_l$ 次。

改变 shift 还可能改变各时间点落在哪一 expert 一侧。减少总步数后，应同时记录两个 expert 各自的执行数、驻留/切换和质量，将实际调用数和各阶段耗时一起比较。这项源码计数确定 benchmark 的工作量分母；对应延迟需要在所选权重和硬件上测量。

从双向 teacher 到少步 AR：CausVid 与 Self Forcing

CausVid 同时改变信息可见范围和采样步数。学生使用 block-causal Attention，同一 chunk 内可并行，后面的 chunk 只依赖已生成历史。训练先用 teacher 的 ODE 轨迹初始化学生，再用分布匹配蒸馏微调；teacher 保持双向上下文，为因果学生提供视频级监督。因此“换成因果 Mask”和“把步数改成 4”都不足以复现该模型，需要配套训练权重。CausVid 论文§4

Self Forcing 进一步针对训练与推理的历史分布差异：训练时按 AR 顺序生成视频，并让后续 chunk 读取模型自己生成的历史 KV。视频级分布匹配损失作用于这些生成序列；少步主干和随机梯度截断控制训练成本。训练时始终读取真实历史的模型，在推理中会遇到自身错误积累，单块重建误差很小也可能逐块漂移。Self Forcing 论文§3

部署时可沿三条线检查。首先是实际去噪时间表与 CFG，二者决定每块求值预算。其次是历史提交：固定的 Self Forcing 推理代码在去噪后还以指定的 context noise 更新 KV。最后是长程窗口：其 causal Attention 实现区分全局与局部索引，并支持保留 sink、滚动淘汰较早的其他历史。配置中的 sink 大小、窗口、位置编码与所用权重一起验证；环形淘汰可以限制历史存储量，长视频中的角色与场景能否持续保持，还取决于模型训练时见过的历史分布。

把这些工作分清，才容易判断剩余成本。假设某个协议每块 4 次去噪、1 次上下文更新，且五次等成本，后者就占主干调用的 20%。这是独立算术例。真实上下文更新还写历史，耗时需要单独测。若想省去它，先证明最后一次去噪所用状态与应提交状态相同，或使用专门为其他上下文协议训练的模型。第12章继续讨论状态读写。

比较 student 与 teacher 时，按第 5 章的近似方法路径评估质量，重点观察条件保持、运动和长程漂移。

如何验证采样改动

固定权重、任务、分辨率、帧数、seed 和初始噪声，先保存原生时间表与分支日志，再改变一种采样因素。比较实际网络调用、每次 batch、可见历史、总 DiT 耗时、完整交付和质量。更换蒸馏 checkpoint 时明确记录权重变化；不要把 teacher 与 student 的差值都归因于 solver。

少步后 Kernel Launch、位置准备、历史搬运和 VAE 占比可能上升。新的瓶颈需要重新 profile，而不是继续按原有主干比例外推。步数、缓存和精度组合的最终结果在第16章按配对实验判断。

第7章 跨步特征复用与自适应缓存

跨步特征复用利用相邻去噪状态的相似性，近似跳过某段网络。收益来自减少实际执行的 block 或子图，不一定减少 scheduler 更新数或外层 model API 调用。将它与原生去噪路径比较，同时检查缓存误差、历史状态和最终视频。

跨步相似性：经验依据与误差边界

TeaCache 论文观察到其测试模型的输出变化随去噪阶段而变，并用输入侧代理估计是否复用。可缓存的子图、需要保留的计算与有效阈值仍由模型适配决定。

Taylor 展开可以帮助理解局部复用的条件。设 $h(t)$ 为沿某条去噪轨迹的特征，$\Delta t$ 为相邻时间步差：

$$h(t-\Delta t)=h(t)-\Delta t\,h'(t)+R_2$$ $$\sup_s\|h''(s)\|\le M\quad\Longrightarrow\quad \|R_2\|\le \frac{M\,\Delta t^2}{2}$$

这个上界要求区间内的二阶导数约束；只看某一点的一阶变化还不足以确定 $M$。轨迹、调度器或条件变化后，局部误差还可能随后续迭代传播。

TeaCache：模型特定代理与工程边界

判定指标与校准

TeaCache 用低于完整主干成本的输入侧代理，估计输出变化并累计决策量，而不是先得到本步真实输出。论文包含 timestep modulation 和 rescaling，具体 proxy 的 Shape 和提取路径要沿模型适配检查。官方代码以下链接固定于 7c10efc4702c6b619f47805f7abe4a7a08085aa0：

  • HunyuanVideo 适配：对图像 token 输入做首个 double block 对应的 norm/modulation，比较该特征张量，随后使用多项式 rescaling；命中时复用图像残差并绕过其实现中的 double/single block 计算，跳过范围由该适配路径确定；
  • Wan2.1 适配：根据配置采用时间嵌入 e 或投影后的 e0，使用匹配型号/任务的系数，并分别维护 conditional/unconditional 状态；保留步与截止步也由适配决定。

抽象地，$p$ 为适配器选定的 proxy tensor，$g$ 为模型特定的重标定函数，$\epsilon$ 为分母保护值，$\tau$ 为待校准阈值：

$$p_t=P_{\mathrm{model}}(x_t,t,c)$$ $$d_t=\frac{\operatorname{mean}|p_t-p_{\mathrm{prev}}|} {\max(\operatorname{mean}|p_{\mathrm{prev}}|,\epsilon)}$$ $$S_t=S_{\mathrm{prev}}+g_{\mathrm{model}}(d_t)$$

$c$ 为条件。缓存有效且 $S_t<\tau$ 时才考虑复用，否则重新计算并重置累计量。

分母保护是这里建议的数值防护，不声称所有官方版本均已实现。$g$、$\tau$、强制重算步和跳过范围需要与模型、权重、分辨率、调度器及步数一起核验；新模型应重新校准阈值。proxy、归约、读写和 host 决策开销也须计入，特别是低 NFE 配置可能几乎没有可复用步。

一个残差缓存骨架

下面用接口伪代码说明缓存状态的组织。假设 adapter 提供 prepare/proxy/region/finish/rescale，rescale 返回单元素 tensor，其中 region 是无额外状态副作用、输入输出同形状的单张量子图；多流、历史 KV 写入、条件更新等需要专用适配。rescale 的负值或非有限结果在此示例中保守触发重算，该策略也需校准。

import math
import torch

@torch.no_grad()
def concept_step(adapter, x, t, cond, state, key, *, threshold,
                 max_skip, force_compute=False, eps=1e-6):
    # key变化即reset；同一个state只服务一条有序去噪轨迹/一个CFG分支。
    if "key" not in state or state["key"] != key:
        state.clear()
        state.update(key=key, prev_mod=None, residual=None, accum=0.0, skips=0)
    h = adapter.prepare(x, t, cond)
    mod = adapter.proxy(h, t, cond).detach().float()
    prev = state["prev_mod"]
    score = math.inf
    if prev is not None and prev.shape == mod.shape and prev.device == mod.device:
        denom = prev.abs().mean().clamp_min(eps)
        delta = (mod - prev).abs().mean() / denom
        score = float(adapter.rescale(delta).item())  # GPU->host决策可能同步
    candidate = state["accum"] + score
    residual = state["residual"]
    compatible = (residual is not None and residual.shape == h.shape
                  and residual.dtype == h.dtype and residual.device == h.device)
    reuse = (not force_compute and compatible and math.isfinite(candidate)
             and score >= 0 and candidate < threshold and state["skips"] < max_skip)
    state["prev_mod"] = mod.clone()  # 每步更新，而不是只在重算时更新
    if reuse:
        h = h + residual
        state["accum"], state["skips"] = candidate, state["skips"] + 1
    else:
        h_in = h.detach().clone()  # region可能原地更新h，不能只保存别名
        h = adapter.region(h, t, cond)
        new_residual = (h - h_in).detach().clone()
        if not torch.isfinite(new_residual).all().item():
            raise FloatingPointError("non-finite cache residual")
        state["residual"] = new_residual
        state["accum"], state["skips"] = 0.0, 0
    return adapter.finish(h, t, cond)

该骨架的阈值、最大连续跳步与强制重算策略均由调用者提供，不构成误差上界。部署前还需补齐：

  • 身份与生命周期：key 覆盖模型/adapter 版本、请求与条件、CFG 分支/强度、shape、dtype、device、调度配置；换请求/权重/条件须 reset，首步、末步和步序跳转按适配策略重算。AR chunk、相机或历史 KV 版本变化时，按模型协议失效缓存；
  • 数值与性能：ε、非有限值及输出检查需要明确定义；.item()、Python 分支、FP32 proxy、clone 和缓存加法都有成本，静态 CUDA Graph 需要另行改写这些 Host 决策；
  • 状态正确性：验证 batch/CFG 布局、mask、位置编码、额外输出和 clean refresh；记录命中、重算次数、峰值与质量。max_skip 限制连续复用长度，由质量评估确定。

AR：chunk 边界也是输入变化

连续 AR 每推进一块，会更新历史、局部位置和相机条件。相邻 chunk 不是同一条去噪轨迹的相邻时间点；默认应重置跨步缓存，只有专门验证过的跨 chunk 算法才允许其他策略。clean refresh 还承担状态写入，应放在无副作用残差缓存之外。

在 4 步去噪中，首尾保留和强制重算后可能只剩很少复用机会。应计算 proxy、归约、host 决策、缓存读写与峰值的完整成本，再决定是否值得整模接入。低 NFE 的 AR 应优先筛选剩余复用机会是否足以覆盖这些固定成本。

同时测执行次数、延迟和质量

FA3 作者说明讨论 Hopper 上的 TMA、异步 Tensor Core 与调度。下面的 RTX 小例使用 PyTorch 2.8.0+cu128 内置的 SDPA flash backend，profiler 中对应 aten::_scaled_dot_product_flash_attention；它没有调用单独安装的 flash-attn Python 包。部署 FA3 或 Blackwell 专用实现时，另行检查该 Kernel 的硬件目标和版本。

TMA 与数据搬运

分块加载的地址生成、寄存器和 shared memory 用量会影响 occupancy。Ampere 已有异步 copy；Hopper 的 TMA 进一步使用 tensor descriptor 描述多维搬运，由专用引擎把数据送入 shared memory，减少部分地址生成与寄存器占用。线程仍负责发射指令、管理 buffer 和同步。

Warp Specialization 与 GEMM/softmax 交叠

Producer 提交 TMA 搬运，consumer warpgroup 执行异步 GEMM、softmax 与归一化。一个 warpgroup 包含 4 个 warp、128 个 thread。WGMMA 的 A 操作数可来自寄存器或 shared memory，B 通过 shared-memory descriptor 读取，累加器保存在寄存器中。

TMA 加载与 WGMMA 计算各有完成依赖，分别通过 barrier 和相应的 fence、commit/wait 协议管理。consumer 先等数据可读，再在使用累加结果前等待矩阵乘完成。FA3 还在 consumer 之间及 consumer 内部交叠 GEMM 与 softmax，减少非矩阵计算暴露的等待。tile 越大可能提高复用，也会增加寄存器/shared memory 压力，最终要看 occupancy 与时间线。作者的流水线说明、PTX WGMMA 协议

分块结果为何仍能形成全局 softmax

对一个 query 行，把 KV 分块。块 $j$ 的 score 为 $s_j$，记录局部最大值 $m_j$、指数和 $\ell_j$ 与未归一化输出 $u_j$： $$m_j=\max(s_j),\qquad \ell_j=\sum\exp(s_j-m_j),\qquad u_j=\exp(s_j-m_j)V_j$$ 合并两块时，先统一指数基准，再相加： $$m=\max(m_a,m_b)$$ $$\ell=e^{m_a-m}\ell_a+e^{m_b-m}\ell_b$$ $$u=e^{m_a-m}u_a+e^{m_b-m}u_b,\qquad O=u/\ell$$ 这就是 online softmax 需要保留的统计量。直接相加两个局部 softmax 输出会丢失各块的相对归一化权重。FlashAttention、split-KV 与 Ring Attention 都需要等价的合并逻辑；mask、全遮蔽行及数值精度仍由具体 kernel 处理。FlashAttention 原论文

FlashDecoding：沿 KV 增加并行度

当 query 很短、KV 很长，且 batch、head、query tile 提供的 CTA 不足时，可以沿 KV 增加并行度。逐 Token Decode 常有这种形状；AR-chunk 则通常一次生成千余至数千个 query token，已经具备较多 query tile。此时 split-KV 增加的并行度是否值得额外规约，要按实际 shape 测量。

线程块如何划分

  • 单 query 的简化映射：若每个 batch/head 仅一个 CTA，batch1/32heads 只有 32 个 CTA，需与整卡 SM 数量及执行波次比较。长 query 的 FlashAttention 还沿 query tile 并行，可调度 CTA 数随之增加；
  • FlashDecoding 机制：将 KV 序列切为 $S$ 个子块，各子块并行计算局部 attention 及 log-sum-exp，再按归一化权重归约。它增加可调度的线程块，也引入中间结果与规约成本；是否改善总延迟取决于 query/KV 长度、head 数、切分与硬件。原始实现说明

SageAttention：量化粒度、补偿与实际 dispatch

Sage 系列把两次矩阵乘中的部分操作数转成低比特格式，以使用更高吞吐的 Tensor Core。输入接口为 FP16/BF16，不代表内部按该精度计算。下表描述论文路线，实际安装包可能提供不同变体：

路线 $QK^\top$ $\widetilde P V$ 与精度处理
Sage1 INT8，比较 per-token/per-block 粒度 准确路径保留 FP16，可采用 FP16 accumulator；另有全 INT8 变体
Sage2 per-thread INT4，并平滑 Q/K E4M3 FP8（含 V 平滑）；用局部 MMA 结果与外部 FP32 buffer 缓解累加误差
Sage3 Blackwell NVFP4 microscaling 同样使用 NVFP4；$\widetilde P$ 另做逐行放大与微块缩放

$\widetilde P$ 指分块 softmax 内部尚未完成全局归一化的指数权重。Sage3 的微块包含 16 个 E2M1 值及 E4M3 scale；若很小的权重直接生成很小的 scale，scale 自身也会丢精度，因此还要逐行缩放。它与“把所有浮点张量 cast 成 FP4”不同。Sage2 的 per-thread 粒度则让 scale 安排匹配线程持有的 MMA 片段，减少更细粒度反量化带来的处理成本。

平滑的等价性可以直接检查。令 $\mu_K$ 为沿 token 轴的均值、$K_c=K-\mathbf1\mu_K$，则 $Q\mu_K^\top$ 对每个 query 行都是常数，因此： $$\operatorname{softmax}(QK^\top/\sqrt d)=\operatorname{softmax}(QK_c^\top/\sqrt d)$$ 若还令 $Q_c=Q-\mathbf1\mu_Q$，就必须补回随 key 变化的项： $$\Delta S=\mathbf1(\mu_Q K_c^\top)$$ $$\operatorname{softmax}(QK^\top/\sqrt d)=\operatorname{softmax}((Q_cK_c^\top+\Delta S)/\sqrt d)$$ 上述等式在实数运算中成立；随后量化仍有误差。$\mu_Q$ 是沿 token 轴求得的逐通道均值向量，不能照抄成全 tensor 共用一个标量均值。Sage2 v2 的算法描述在分块前对整张 $Q$ 求逐通道 token 均值，Sage3 v3 则按每个 query block（query tile）计算 $\mu_{Q_i}$；实际部署应按所选版本与 Kernel 核对平滑范围及补偿项布局。V 若减去 token 均值，则归一化输出还要加回该均值。

收益来自更快的矩阵指令，代价包括统计 scale、打包、布局转换和补偿。预处理工作量约随 $(M+N)d$ 增长，矩阵乘约随 $MNd$ 增长；长 query 更容易摊薄前处理，短 query 反复重新量化长 KV 则可能更慢。因此应同时测量前处理、Attention Kernel 与两者合计时间。

部署时应记录实际函数、GPU、layout、mask、head dimension 与累加配置。例如固定官方 API 清单仍有 qk_int8_pv_fp16、qk_int8_pv_fp8 变体，不能由“Sage2”名称断定该实验执行 INT4。Benchmark 应包含格式转换与 attention 总时间，另报纯 kernel 时间，并在相同输入上验数值与长片段质量。Sage3 的数值与性能仍需在目标模型上单独测量。

第9章 稀疏、Token 压缩与替代 Attention

稀疏和 Token 压缩减少的工作不同：前者通常删去部分交互，后者还可能减少后续投影和 MLP 的 token 数。替代 Attention 进一步改变计算形式。选择时应看完整 block 节省了什么、额外做了什么，以及模型是否为该路径训练。

结构化稀疏与近似注意力

Sliding Tile Attention：让局部窗口对齐计算 Tile

逐 Token 滑窗在二维或三维展平后，往往产生既有有效位置又有被遮蔽位置的 mixed tile。Kernel 仍要计算这些 tile，再对部分元素施加 Mask，位置稀疏率就难以转成等比例计算节省。STA 把视频重新排列成连续的时空 tile，让同一个 query tile 共享局部 key 窗口；窗口内按完整 dense tile 计算，窗口外整块跳过。这样局部性和 Tensor Core 的计算单位能够对齐。STA 论文§2–3

窗口大小决定质量与工作量。论文分别讨论 training-free 的 Mask 搜索和微调配置；部署时将窗口、head/layer 配置和对应权重一起保存。更大的空间运动或跨场景依赖可能需要窗口外信息，移植到矩形 AR Attention 时还要处理历史边界。

Sparse VideoGen：按 head 选择空间或时间模式

SVG 观察到一些 head 偏重同帧空间区域，另一些偏重跨帧时间关联。它用少量 query 的在线采样比较候选稀疏模式与 dense 输出，选择误差较小的模式，再以相应布局和 Kernel 执行。空间、时间访问在原始展平布局中具有不同 stride，重排的作用是让保留的 KV 尽量连续，减少低效访存。SVG 论文§4、官方实现

模式识别、采样参考、重排和还原都是实际成本。序列较短时，这些逐步开销更难由 Attention 计算节省覆盖。减少 NFE 后，编译和初始化等一次性成本的占比可能上升；逐步开销则按实际调用次数统计。SVG 的 training-free 路径、STA 的窗口设计与下面需要匹配训练的 VSA 是不同路线，选择时先确认自己的质量与训练预算。

Video Sparse Attention：粗粒度路由与细粒度计算

VSA 按内容选择 block，而不是固定保留空间邻居或运动轨迹。原论文§2.2 与 Appendix A把视频 token 按时空 cube 重排，默认一个 $4\times4\times4$ cube 包含 64 个 token。query cube 与 key cube 形成的 score tile 才是 $64\times64$；两种尺寸不能混用。

粗阶段对每块 Q/K/V 取均值，计算 cube 之间的 attention，并逐行 Top-K 选出细阶段要计算的块。细阶段在选中块内部执行 token-level attention。粗输出也参与最终结果，不是仅生成 mask：

$$Q_c,K_c,V_c=\operatorname{MeanPoolTiles}(Q,K,V)$$ $$A_c=\operatorname{softmax}(Q_cK_c^\top/\sqrt d)$$ $$m=\operatorname{ExpandTileMask}(\operatorname{RowTopK}(A_c))$$ $$O_f=\operatorname{softmax}(QK^\top/\sqrt d+\operatorname{mask}(m))V$$ $$O_c=\operatorname{BroadcastTiles}(A_cV_c),\qquad O=G_c\odot O_c+G_f\odot O_f$$

$\operatorname{mask}(m)$ 将保留连接映射为 0，其余连接映射为 $-\infty$。

门控与主干需要匹配训练；适配预训练模型时，论文将 fine gate 固定为 1，coarse gate 从 0 开始学习。时空重排让一个 cube 的 token 连续存放，细阶段可以按整块消费，避免逐 token 不规则 gather；粗路由、Top-K、重排与融合仍有成本，稀疏率不能直接换算成整层加速。论文中的训练收益和配套权重也不能替代在 AR-chunk 矩形 attention、相机位置协议上的适配验证。

稀疏与线性混合注意力：SLA (Sparse-Linear Attention)

SLA 用稀疏 softmax 与经过训练的线性分支互补。论文 v2 Eq.5–6的输出还包含可学习投影： $$Y_{\text{SLA}}=Y_{\text{sparse}}+\operatorname{Proj}(Y_{\text{linear}})$$ 论文用压缩 mask 聚合 marginal blocks；SLA 固定源码则先对全 KV 计算线性分支，再投影相加。两种版本的线性分支都依赖匹配训练、配套权重和原生位置/条件协议。

稀疏率之外的成本与误差

动态路由、Top-K 和 packing 可能抵消少做的 Attention 乘法。逐 Token 索引容易产生不规则 gather，整块选择则更便于保持连续读取。记录 router → packing → attention → restore 的完整时间，同时保留各阶段 trace，才能判断改进应落在哪一处。

被删位置的概率质量比位置比例更接近误差来源。若被删位置的累积注意力概率质量为 $p_{\mathrm{drop}}\in[0,1)$，保留和删除部分各自归一化后的输出为 $O_{\mathrm{keep}}$、$O_{\mathrm{drop}}$，则：

$$O_{\mathrm{dense}}=(1-p_{\mathrm{drop}})O_{\mathrm{keep}}+p_{\mathrm{drop}}O_{\mathrm{drop}}$$ $$O_{\mathrm{keep}}-O_{\mathrm{dense}}=p_{\mathrm{drop}}(O_{\mathrm{keep}}-O_{\mathrm{drop}})$$

同样删除 90% 的位置，$p_{\mathrm{drop}}$ 可以很小，也可以很大。路由需要找到对当前 query 有用的连接；剩余连接重新归一化后，误差还会受 V 的幅值与方向影响。先检查 Mask、位置和历史可见性，再按第 5 章的近似方法路径评估视频质量。

Token pruning 与 merging 改变整个子图的几何

设原序列长度为 $N$、处理后的有效长度为 $rN$，$0<r\leq1$。若压缩发生在整个 block 之前、且后续都使用缩短序列，理想 GEMM 主项随 $r$ 缩小，dense attention 主项随 $r^2$ 缩小；若只在 Attention Core 内压缩 K/V，QKV 投影或 MLP 可能完全未减少。需要明确插入位置，才能解释 token 保留率带来了多少计算节省。

merging 还要计算相似度、选配对、聚合和 unmerge；pruning 要定义删去位置如何影响后续空间重建。保留 Shape 恢复路径不表示内容精确恢复，跨模态和运动边界也可能被错误合并。ToMe for Stable Diffusion是可查的图像扩散示例，不是现成的 Wan2.2 或 SolarWM 视频适配。

$$T_{\mathrm{candidate}}=T_{\mathrm{select}}+T_{\mathrm{pack}} +T_{\mathrm{reduced}}+T_{\mathrm{restore}}$$ $$\Delta T=T_{\mathrm{original}}-T_{\mathrm{candidate}}$$

只有 $\Delta T>0$ 且质量通过才有采用依据。上述 $r$ 和 $r^2$ 描述理想计算量，延迟还包含选择、重排与恢复的成本。

双向与 AR 的验证差异

Wan2.2 需要检查时空邻域、运动位置和 cross-attention 条件保持；两份 expert 可能需要分别校准。一个匹配某个 expert 的 mask 或门控权重不能直接用于另一份网络。若稀疏只改 Attention Core，量化、QKV、MLP 及 expert 切换仍按原路径计时。

连续 AR 还需要保证当前 query 可见正确历史、局部位置和相机对应一致。动态选择不能从未来块读取信息，也不能把物理 ring 槽号当时间位置。逐块差异可能经过未来生成放大，因此短 chunk 数值接近只是一项筛选，不能替代多次淘汰后的质量。

路由、packing、转换与 attention 分开诊断后，回到无插桩完整路径计时。若候选变慢，保留同 dtype/backend 的分因子对照，定位增加的成本来自路由、布局还是主 Kernel。

第10章 Linear/GEMM 与低精度计算

Linear 的耗时由 GEMM 的 $M/N/K$、布局和执行精度共同决定。Attention 融合或稀疏化以后，QKV 投影与 MLP 可能成为新的瓶颈。低精度路径要节省矩阵计算或读取时间，并覆盖量化和布局转换成本。

把 DiT Linear 展开成 GEMM

设 hidden states 为 $[B,N,D]$，将 batch 和序列展为 $M=B\times N$。以 Q/K/V 同宽的 MHA 为例，QKV 投影为 $[M,D]$ 乘 $[D,3D]$，输出投影为 $[M,D]$ 乘 $[D,D]$；MLP 再按原生 ffn_dim 展开。GQA/MQA 需按实际 KV 头数重算投影宽度，不同层的隐藏宽度与门控形式也应从配置读取。

第 3 章给出了理想算术强度。实际选型还需要确认 weight layout、transpose、bias/activation epilogue、batch 组织和 padding。小 $M$ 时压缩权重可能减少读取量，大 $M$ 时低精度 Tensor Core 可能改变计算预算；AR-chunk 的 $M$ 是当前块的有效 Token 数（常在千余至数千量级），远大于逐 Token LLM Decode 的 $M=1$，应按真实 Shape 选 Kernel。

一个 Per-Tensor 量化算例

在 Per-Tensor 量化中，整个矩阵共享唯一的缩放因子（Scale Factor）$S$： $$S = \frac{\max(|X|)}{q_{\max}}$$ 以有符号 4-bit 量化为例（$q_{\max} = 7$），若矩阵中存在一个离群值 $\max(|X|) = 112$： $$S = \frac{112}{7} = 16$$ 量化公式为： $$Q(x) = \text{clamp}\left( \left\lfloor \frac{x}{S} \right\rceil, -8, 7 \right)$$ 对于占绝对多数的平常特征（$x \in [-1.5, 1.5]$）： $$\frac{x}{S} \in \left[ -\frac{1.5}{16}, \frac{1.5}{16} \right] \approx [-0.09375, 0.09375]$$ 这些值舍入后都变成 0，反量化也无法恢复其差异。这里的误差发生在舍入阶段：共享 scale 太大，小幅值信息落入同一个量化区间。实际质量影响取决于这些通道及后续计算，可用逐层回放定位敏感层。

分块量化与低秩补偿

细粒度 Block-wise FP8 量化

分块量化将全局 scale 拆成局部 scale，使一个区域的离群值不再决定其他区域的量化分辨率：

  • 分块规格：128 元素是一种候选粒度；一维分组与二维 tile 的 scale 布局不同，须与所选 kernel 配套；

  • 计算流（E4M3 示意）： $$X_{\text{FP8}} = \text{cast}_{\text{FP8}}\!\left(\text{clamp}\left(\frac{X}{S_{\text{block}}},-448,448\right)\right), \quad \hat X = S_{\text{block}} X_{\text{FP8}}$$ scale 计算需处理全零块；cast 包含舍入，单纯 clamp 并未完成 FP8 编码。

  • 布局与实际成本：128 个 FP8 元素的载荷为 128 字节；另计 scale、对齐和重排，并检查 warp 实际发出的访存事务；

  • 校准范围：覆盖目标分辨率、提示词及去噪区间；按模型和输出任务制定精度阈值。

SVDQuant：4-bit 奇异值低秩分解

SVDQuant 先把 activation 的离群幅度转移到 weight，再用高精度低秩分支吸收 weight 中的大奇异分量；分解对象是平滑后的权重。以下按列向量记号重写原论文§4.2，省略 bias。

设 $X\in\mathbb R^{D_{\text{in}}\times N}$、$W\in\mathbb R^{D_{\text{out}}\times D_{\text{in}}}$，选择正对角平滑矩阵 $S$： $$\widetilde X=S^{-1}X,\qquad \widetilde W=WS,\qquad WX=\widetilde W\widetilde X$$ 增大离群 activation 对应的 scale 会缩小该输入通道，同时放大对应 weight 列。对 $\widetilde W$ 做截断 SVD，取 rank 为 $r$ 的 $L_1L_2^\top$，再定义剩余权重： $$R=\widetilde W-L_1L_2^\top$$ 其中 $L_1\in\mathbb R^{D_{\text{out}}\times r}$、$L_2\in\mathbb R^{D_{\text{in}}\times r}$。低比特路径处理 $R$ 与 $\widetilde X$，高精度路径保留低秩项。用 $\mathcal D_4(A)$ 表示 4-bit 量化再反量化后的数值，得到： $$\widehat Y=\mathcal D_4(R)\mathcal D_4(\widetilde X)+L_1(L_2^\top\widetilde X)\approx WX$$ 这是数值分解，不要求 kernel 实际物化反量化矩阵。rank、平滑与分组会共同影响误差、参数量和延迟，应作为配方的一部分记录。

AdaLN 调制的访存开销

以 DiT 核心的自适应层归一化（AdaLN-Zero）为例： $$\tilde{X} = \text{LayerNorm}(X) \cdot (1 + \gamma) + \beta$$ 假定调制参数 scale=1+γ 与偏置 $\beta$ 已就绪，在未融合的 Eager 路径下，归一化、逐元素乘法和加法各自独立执行：

  1. LayerNorm 读取输入 $X$，计算均值与方差，将标准化结果写回显存；
  2. 乘法重新从显存读取标准化结果与 scale，写回乘积；
  3. 加法再次读取乘积与偏置 $\beta$，写回最终调制结果。

这类逐元素与归约操作算术强度很低，耗时往往受限于显存带宽与密集的 Kernel 发射空档。

融合与 Graph Break

torch.compile 默认的 TorchInductor 后端会自动融合相邻的逐元素与归约算子，省去中间张量落盘；若进一步指定 mode="reduce-overhead"，编译器还会尝试用 CUDA Graph 包装无图断裂的子图以削减 Host 发射开销（与下一节显式管理静态 CUDA Graph 互补）。若代码中包含无法静态追踪的控制流，编译器会发生图断裂（graph break），在 fullgraph=True 下则会直接报错。排查时可开启日志：

TORCH_LOGS="graph_breaks" python inference.py

常见触发点包括：

  1. 标量提取与数据相关 Python 控制流：如在热路径中调用 t.item() 或 if t > 500: 触发隐式设备同步；
  2. 自定义算子缺失元数据推导：第三方 C++/CUDA 算子未注册 fake/meta 实现；
  3. 热路径插桩：依赖 GPU 张量数值的日志、断言或 NaN 检查，应移出编译与计时区域。

CUDA Graph 静态图捕获与显存池管理

输入输出形状与执行拓扑固定的前向子图适合用 CUDA Graph 捕获。录制单次 block 前向还是整个去噪步，取决于 scheduler 更新、条件切换和跨卡通信如何组织；本章小例先隔离测量一个固定算子栈的发射收益。

录制前置条件与约束

捕获与 replay 需要满足三项基本约束：

  1. replay 地址与生命周期稳定：静态输入、输出 buffer 及模型参数地址在重放期间必须保持有效。捕获区域内部的中间张量分配由 capture allocator 接管并保留在 graph 私有内存池中，torch.empty、torch.zeros 本身无需手工改写为外部预分配；
  2. 捕获区域内禁止主机同步：.item()、依赖 GPU 结果的 Python 分支和阻塞式 CPU 拷贝必须移出捕获范围；预热、同步计时与数值校验统一放在 graph 外部；
  3. replay 拓扑与几何匹配：单个 graph 严格重放捕获时录下的算子序列与内存地址，动态变化的标量（如当前时间步 embedding）可通过向固定 device buffer 原地 copy_ 来更新；不同分辨率或分支路径则需分别维护独立 graph。Graph 实测案例

共享显存池（Mempool Sharing）与生命周期

  • 显存成本：每个 CUDA Graph 的私有池会在 graph 存续期间保留已分配显存。为多个 Shape 或 expert 分别捕获独立 graph 时，reserved 显存随之累加；
  • 池复用方案：当多个 graph 按捕获顺序严格串行重放、且前一次重放的输出张量在被下一次重放覆盖前已消费完毕时，可通过 graph_pool_handle() 共享同一个显存池：
# 仅示意共享池接口；复用前核验重放顺序与输出生命周期
mempool = torch.cuda.graphs.graph_pool_handle()
with torch.cuda.graph(g, pool=mempool):
    output = model(static_input, static_t, static_c)

用访存账本判断融合机会

仍以 $Y=\operatorname{Norm}(X)\times\mathrm{scale}+\mathrm{bias}$ 为例，令 $X$ 含 $E$ 个元素、每元素占 $b$ bytes，忽略较小的 scale/bias 广播与均值方差统计量时，分离执行与理想融合的激活读写下界对比如下：

路径 激活读写 载荷下界
Norm 读 $X$，写 $U$ $2Eb$
Multiply 读 $U$，写 $V$ $2Eb$
Add 读 $V$，写 $Y$ $2Eb$
分离合计 三阶段分别读写 $6Eb$
理想融合 读 $X$，写 $Y$ $2Eb$
理想减少量 中间激活读写 $4Eb$

账本给出了理想节省的中间激活流量；实际提速幅度还受 L2 cache 命中率与融合 Kernel 的寄存器压力影响。将 RoPE 融入 QK 准备、或将 bias/激活函数融入 GEMM epilogue 时，需确保融合不会迫使原本走高效库函数的 GEMM 退化为慢速自定义 Kernel。

只预计算真正的不变量

在多步去噪循环中，固定文本 prompt 的 encoder 输出、跨步不变的 cross-attention 条件 K/V，以及固定窗口几何下的旋转位置编码表（RoPE cos/sin），都可以提到去噪循环之外预计算一次。相反，依赖当前噪声步 $t$ 或动态相机姿态的分支则必须按步更新。

固定步序的 AdaLN 调制查找表

当采样时间步序列、输入条件和模型权重在单次请求内固定时，各去噪步的逐层 AdaLN 调制向量可以在进入去噪主循环前一次性批量算出，存为紧凑的查找表（LUT）。设网络共有 $L$ 层、每层包含 $M$ 组独立条件调制分支、输入条件宽度为 $D_{\mathrm{in}}$、隐藏层宽度为 $D$，每组输出 6 个调制向量（如 double block 的 shift/scale/gate），采样共 $S$ 步、每元素占 $b$ 字节，忽略 bias 时：

$$P_{\mathrm{proj}}=6LMD_{\mathrm{in}}D,\qquad M_{\mathrm{LUT}}=6SLMD\,b$$

其中 $P_{\mathrm{proj}}$ 是调制线性层的静态参数量，$M_{\mathrm{LUT}}$ 是预计算查找表的显存载荷。由于时间步数 $S$ 远小于 $D_{\mathrm{in}}$（例如 $S \in [4, 50]$，而 $D_{\mathrm{in}}$ 通常为数千），$M_{\mathrm{LUT}}$ 往往只有数十至上百 MiB。将步序固定的调制投影合并到循环外预计算，一方面能把多步小矩阵乘合并为一次批处理并省去循环内的重复发射，另一方面在支持权重 Offload 的部署中，若后续去噪步不再直接调用调制线性层权重，还可按需释放这部分投影权重的常驻占用。

位置与相机变换的原地子向量操作

三维时空 RoPE（如 MM-RoPE）或相机射线旋转编码（PRoPE）常需将每个注意力 head 的通道维 $d$ 切分为多个子区间（例如仅对特定子向量施加平面正交旋转，其余维度保持不变）。朴素实现往往先沿最后一维 split 切片，分别计算旋转后再调用 torch.cat 重新拼接回 [B, N, H, d]。在长序列、数十层、多步去噪的累积调用下，反复 split + cat 不仅增加短 Kernel Launch，还会频繁触发完整 Q/K 张量大小的临时显存分配与拷贝。

将这类变换改写为基于步幅（strided view）的原地子向量操作，或者直接融入 QK 归一化与位置编码的自定义 Triton/CUDA Kernel，可以直接在原张量的目标通道切片上完成二维旋转写入，省去跨步拼接产生的中间缓冲与带宽消耗。

此外，推理阶段固定的 LoRA 分支也可以在加载时直接合并（merge）进主干权重副本，省去每次前向的额外低秩旁路计算。合并与权重量化的先后次序会影响舍入误差，上线前需在代表性提示词集上核对数值与画面一致性。

Regional compilation 与冷启动预算

对结构完全重复的数十个 DiT Block，优先对单个标准 Block 启用区域编译（regional compilation），让编译器复用同一套生成代码，能够显著缩短首次编译的冷启动耗时。PyTorch 官方教程

设编译带来的额外初始化耗时为 $C$ 秒，编译后每次请求净节省 $d$ 秒（$d>0$），则摊平冷启动成本所需的最小请求数为 $\lceil C/d\rceil$。在多分辨率或多帧数规格并存的线上服务中，还需结合编译缓存命中率与重编译触发频率评估实际收益。

双向与 AR 的捕获范围

第12章 AR 历史 KV 与状态管理

AR 历史 KV 保存已生成上下文的执行状态。优化对象除了 tensor 本身，还包括有效窗口、逻辑位置和提交时机：任何一项变化都会进入未来 chunk 的输入。本章用公开 SolarWM 源码解释状态生命周期，用合成 CPU 小例比较 list 与 ring，并结合 50 层 AR 规模的合成微基准分析活跃窗口与分页池的容量和提取开销；基础容量公式见第 4 章。

这里的时间坐标方向与第 6 章相反。第 6 章取 $t=0$ 为数据端、$t=1$ 为噪声端；SolarWM 的 flow 实现则使用 $u=1-t$：

$$x_u=u\,x_{\mathrm{data}}+(1-u)\,\epsilon,\qquad u=1-t$$ $$v_u=x_{\mathrm{data}}-\epsilon,\qquad \widehat x_{\mathrm{data}}=x_u+(1-u)\widehat v_u$$

因此其 clean refresh 传入 timestep 参数 $u=1.0$（即第 6 章的 $t=0$，纯数据端）。不同代码库对 timestep 的正反向定义各异，对照采样日程时需先核对噪声系数的映射关系。

是否需要单独的 refresh 前向，取决于训练与推理约定的上下文协议。例如 Causal-rCM采用自身的 APPEND 路径。若想省去额外前向，前提是验证最后一步去噪状态与下一块训练时所见的历史分布兼容。

有界窗口与环形存储

固定窗口模型在填满窗口后只保留规定数量的最近历史块，KV 显存随窗口大小封顶，而非随总视频时长无限增长。有界 list 即可限制保留块数；环形池（ring buffer）则进一步复用预分配的固定物理槽位，避免在滚动生成中频繁分配和释放大张量。

沿用第 2、4 章记号，设窗口保留 $K$ 个历史 chunk（当前去噪块另计，代码中亦常记为 W_history），每层 K/V 缓冲池可组织为 [B, K, N_chunk, H_KV, d]。下面以 $K=5$ 槽位环形池示意覆盖写入：

生成块编号 $k$ 从 0 开始时，当前块的写入槽位为：

$$s=k\bmod K$$

若将槽位与块内 Token 轴展平，则对应连续切片 [s*N_chunk:(s+1)*N_chunk]，可通过 copy_ 原地覆盖最旧槽位。当环形池发生环绕后（例如逻辑顺序对应物理槽位 [3,4,0,1,2]），若算子依赖时间顺序或局部相对位置，读取时仍需按逻辑块序重组或通过索引表映射，这部分准备开销应与 Attention Kernel 一并衡量。

逻辑位置与物理槽位分开保存

物理槽位循环复用，而数学上的时间与相机位置则随生成推进持续递增。因此状态管理器必须将物理存储槽号与逻辑 chunk/帧 ID 及相机外参分开记录。

公开 SolarWM Attention在历史池中保存的是 QK Norm 之后、MM-RoPE/PRoPE 旋转之前的 raw K 与 V。每次前向读取时，先将当前块 query 与窗口内可见历史映射到当前窗口的局部相对位置，施加位置与相机旋转变换后送入 Attention，而池中的 raw KV 保持不变。这样当滑动窗口向前滚动时，历史块可以在新窗口坐标系下重新计算相对旋转；反之，若模型缓存的是绝对位置编码后的 post-RoPE K，则需配套相应的相对位移重标定策略。

KV 精度、布局与量化开销

单层历史逻辑上为 [B, N_history, H_KV, d]，物理上可存为 chunk 列表、连续预分配池或分页池（paged cache）。若将历史 KV 压缩为 FP8，需明确量化作用在 raw K/V 还是 post-RoPE K/V 上，并计入缩放因子（scales）与对齐开销：

$$M_{\mathrm{BF16}}=2BN_{\mathrm{history}}H_{\mathrm{KV}}d\times2\ \mathrm{B}$$ $$M_{\mathrm{FP8,payload}}=2BN_{\mathrm{history}}H_{\mathrm{KV}}d\times1\ \mathrm{B}$$ $$M_{\mathrm{FP8,total}}=M_{\mathrm{FP8,payload}}+ M_{\mathrm{scales}}+M_{\mathrm{padding}}+M_{\mathrm{metadata}}$$

式中前导因子 2 对应 K 与 V 两份张量。对于缓存 raw KV 的模型，读取反量化后的误差还会经过后续的 RoPE 与相机旋转变换，并在自回归生成中逐块传递。

分页结构适合多请求并发服务中变长历史的动态拼装，能减少外部内存碎片；而在单请求、固定窗口长度的连续 AR 视频生成中，按块对齐的连续预分配池往往索引更简单、访存更连续。

$$M_{\mathrm{active}}=2\times50\times6000\times56\times128\times2 =8{,}601{,}600{,}000\ \mathrm{B}\approx8.60\ \mathrm{GB}\ (8.01\ \mathrm{GiB})$$

从持久池到异步预取

如果层 $l+1$ 的历史读取不依赖层 $l$ 的输出，可提前搬运到另一组目标。消费者读取前等待 copy ready，目标复用前等待旧消费者完成；Host 源保留到 DMA 结束。双 buffer 会增加同时存活量，预取距离要与激活显存共同安排。

$$T_{\mathrm{ideal}}\approx\max(T_{\mathrm{compute}},T_{\mathrm{copy}}) +T_{\mathrm{unhidden}}$$ $$\Delta T=T_{\mathrm{original}}-T_{\mathrm{prefetch}}$$

$T_{\mathrm{unhidden}}$ 为无法隐藏的准备与等待，$T_{\mathrm{prefetch}}$ 包含预取及同步。

达到这个理想关系需要独立工作、足够 DMA/计算资源与正确依赖。上述实验只测同一 Stream 上的搬运，因此下一步是集成 copy/compute 两条时间线，测等待是否被隐藏，再回到无插桩整模对照。

实现细节可查 PyTorch CUDA 语义和官方 pin/nonblocking 教程。non_blocking=True 表达的是提交行为，重叠是否发生要从实际时间线确认。

第14章 多 GPU 并行与通信

多 GPU 并行切分服务于三个不同目标：缩短单请求延迟、容纳单卡放不下的模型与激活、提升多请求并发吞吐。不同目标对应的切分维度与通信模式各异。本章基于公开实现推导张量并行（TP）、序列并行（SP）与分层放置的理论通信量；实际部署时需将集合通信、布局转换和流同步等待放在同一时间线上核验。

张量并行的层内通信

标准 Megatron 风格的 TP 在 Transformer Block 内交替使用列并行（Column Parallel）和行并行（Row Parallel）：QKV 投影按列切分，各 rank 独立计算本地注意力头；输出投影按行切分，再通过 All-Reduce 合并各 rank 对残差分支的贡献；MLP 的升维与降维同样按列、行配对切分。

在该布局下，每个 Block 单次前向包含两次逻辑 All-Reduce。若模型有 50 层、单次请求执行 40 次主干前向，则会触发 $2\times50\times40=4000$ 次集合通信。即便每次传输的张量不大，数千次高频通信的启动延迟与同步屏障也会直接进入关键路径，因此 TP 通常依赖高带宽、低延迟的片间互联（如 NVLink）。

PCIe 标称线速与显存带宽只代表硬件上限，跨卡通信预算必须基于目标消息大小下的实测有效带宽。以 GeForce RTX 5090 等消费级显卡为例，NVIDIA 在 2025 年 3 月的公开说明明确其官方支持范围不包含跨卡 GPU P2P 直传；在此类拓扑上规划多卡并行，必须将经由 Host 内存转发（Host staging）的开销纳入考量。

Ulysses 的两次转置

DeepSpeed Ulysses在 QKV 线性投影和 MLP 阶段让各卡独立处理本地的 $N/P$ 序列切片，进入 Attention Core 时切换为按注意力头（head）分工。设标准 MHA 的头数满足 $H\bmod P=0$（若为 GQA 则需按 KV 头数重算切分或复制策略）：

  1. 第一次 All-to-All：将 [N/P, H, d]（切序列、全 head）转置为 [N, H/P, d]（全序列、切 head），Q、K、V 一并跨卡重排；
  2. 本地 Attention：每张卡对分到的 $H/P$ 个 head 计算完整序列长度 $N$ 的注意力；
  3. 第二次 All-to-All：将输出从 [N, H/P, d] 转回 [N/P, H, d]，交由后续输出投影和 MLP 继续按序列切片处理。

设并行度为 $P>1$、序列长度为 $N$、隐藏维度为 $D$、每元素占 $b$ 字节，均匀切分下每张卡的 Attention Core 计算量与跨卡发送载荷为：

$$F_{\mathrm{core,rank}}\approx\frac{4N^2D}{P},\qquad M_{\mathrm{send,rank}}\approx\frac{(3+1)NDb(P-1)}{P^2}$$ $$\frac{F_{\mathrm{core,rank}}}{M_{\mathrm{send,rank}}} \approx\frac{NP}{(P-1)b}$$

固定卡数 $P$ 时，稠密 Attention 的计算量随 $N^2$ 增长，而 All-to-All 通信量仅随 $N$ 线性增长，因此序列越长，计算越容易掩盖或摊薄通信占比。反之，当序列较短或卡数 $P$ 很大时，高频 All-to-All 的启动开销与转置重排就会凸显。

Ring Attention 的分块交换

Ring Attention让每张卡始终持有本地的 $N/P$ 个 query，同时将各卡的 K/V 切片沿逻辑环逐跳传递。每一跳计算当前本地 query 对收到 K/V 分片的局部注意力，并按第 8 章的 online softmax 递推公式更新全局最大值与归一化分母。

工程实现上常借助 dist.P2POp 与 dist.batch_isend_irecv 在后台通信流上异步收发下一跳的 K/V 分片，同时在计算流上执行当前分片的 Attention。要实现理想的计算-通信重叠，单跳计算耗时（约 $4(N/P)^2D$ FLOPs）必须足以覆盖单跳 K/V 传输耗时（$2(N/P)Db$ 字节）；在经由 Host 内存转发或带宽受限的链路中，分片过细反而会放大每次收发的调度延迟。PyTorch 2.8 通信 API

xDiT/USP：在两个并行维度之间选组合

USP（Unified Sequence Parallelism）将 Ulysses 的按头切分与 Ring 的分块环传组合成二维网格：Ulysses 维度受限于注意力头数（如节点内走高带宽 NVLink 做 All-to-All），Ring 维度继续扩展并行卡数（如跨节点或跨组传递 K/V）。xDiT在此基础上集成了面向扩散主干的混合并行管线。选型时需结合模型真实 KV 头数、序列长度和机器互联拓扑扫描 (Ulysses, Ring) 组合，并计入转置 reshape、padding 及非并行模块的完整耗时。

Host 中转时，优先减少通信频率

当硬件不支持 GPU P2P 直传、通信退化为 Host staging 时，每次跨卡传输都需经过两段 PCIe 链路与主存缓冲：

$$\text{GPU 0}\xrightarrow{\text{PCIe}}\text{Host memory}\xrightarrow{\text{PCIe}}\text{GPU 1}$$

在这样的拓扑上，每层触发数次 All-Reduce（TP）或 All-to-All（SP）很容易让 PCIe 与 CPU 内存控制器成为瓶颈，导致多卡比单卡更慢。若首要目标是解决单卡显存容量不足，采用粗粒度按层放置（Pipeline / Layer Placement）——例如将前一半 Block 放在 GPU 0、后一半放在 GPU 1，仅在层间交界处传递一次残差激活——能将每步主干前向的跨卡通信从上百次压缩到一两次。

CFG、权重切分与 DP

对于包含正负双分支的 CFG 去噪，CFG Parallel 将 conditional 与 unconditional 分支分配给不同 GPU 并行执行，每步只需交换一次预测结果即可将单卡分支计算负载减半，理想情况下使分支计算阶段的关键路径接近减半；总计算量并未减少，实际收益还需计入通信同步、分支负载差异以及拆掉单卡双分支合批（2B）后的算子利用率变化。当单卡可驻留权重且互联开销可控时，它常是 2 卡配置的优先候选；若模型已做单分支 CFG 蒸馏，则优先转向 SP 或数据并行（DP）。

当单卡放不下模型权重时，FSDP 风格的权重分片在每层前向时按需 All-Gather 权重，以通信换容量；而离线批量生成或多并发服务则可通过 DP 在各卡独立跑不同请求，获得近似线性的聚合吞吐扩展。

双向视频与 AR-chunk 的选择顺序

Wan2.2 的全序列双向生成序列长、包含双分支 CFG，适合优先评估 CFG Parallel 与 Ulysses/Ring SP（参考 SGLang Diffusion 并行对比）。而连续 AR-chunk 单次前向的当前块 query 相对全序列较短（常在千余至数千 token）、历史 KV 较长，单块计算量显著小于全序列扩散；优化决策应先评估单卡全量驻留与局部算子加速，避免把本可留在显存的活跃 KV 无故搬往 Host 引入额外传输开销。仅当单卡显存不足且确需外移历史时，再评估持久锁页 KV 卸载与异步预取；确实需要多卡扩展时，再结合互联带宽与 query/KV 长度比较低开销的 Ulysses 小度数切分或粗粒度分层放置，避免高频层内通信无法被短 query 计算摊平。

第15章 VAE、流式执行与端到端交付

从 latent 到客户端可播放画面，还需经过 VAE 解码、重叠区融合、音视频混流编码与网络传输。当 DiT 主干通过少步蒸馏、缓存与低精度算子大幅提速后，外围解码与交付链路往往上升为新的端到端瓶颈。

VAE：先区分容量优化和计算优化

3D 视频 VAE Decoder 包含大量高分辨率时空卷积与上采样层，特征图在空间和时间展开后往往比 DiT 主干占用更多瞬态显存。优化 VAE 时需先分清目标是压低显存峰值（防 OOM）还是缩短解码耗时。

Tiling 降低峰值，也会重复工作

空间分块解码（Spatial Tiling）将 latent 切分为带重叠边界（overlap）的局部瓦片逐块解码，从而大幅降低单次卷积激活的显存峰值。但重叠区域会被相邻 tile 重复计算；粗略按二维覆盖面积衡量，总解码面积相对整幅画面的倍数（覆盖面积比）为：

$$r_{\mathrm{area}}\approx \frac{n_{\mathrm{tile}}h_{\mathrm{tile}}w_{\mathrm{tile}}}{A_{\mathrm{full}}}\ge 1$$

其中 $n_{\mathrm{tile}}$ 为瓦片数，$h_{\mathrm{tile}},w_{\mathrm{tile}}$ 为单瓦片尺寸，$A_{\mathrm{full}}$ 为完整画面面积；因重叠而多出来的重复计算比例（冗余面积占比）则为 $r_{\mathrm{area}}-1$。瓦片切得越碎，重叠区重复计算和 Kernel Launch 越多，解码总延迟通常越长。因此实践中应在显存预算允许的范围内尽量选用较大的 tile 尺寸。

为消除瓦片拼接处的亮度和纹理接缝，重叠区通常采用余弦窗（Hanning window）或线性渐变加权融合。设 $x\in[0,\delta]$ 为重叠区内的相对坐标，平滑过渡权重可取：

$$w(x)=\frac{1}{2}\left[1-\cos\left(\frac{\pi x}{\delta}\right)\right]$$

所有覆盖同一像素位置的瓦片输出按权重归一化相加。空间加权能消除静态接缝，但如果时序维度缺乏上下文，画面仍会出现跨帧闪烁。

时间状态跟着 codec，而不是生成块大小

视频 VAE 的时序下采样/上采样层可能是因果卷积（依赖历史帧特征缓存）或非因果卷积（需要前后帧 lookahead）。在按 chunk 流式解码时，不能把每个生成 chunk 当作孤立短视频直接调一次无状态 decode()——那样会在每个 chunk 边界丢失前一帧的时序卷积状态，导致周期性跳帧或闪烁。

例如 Diffusers v0.35.1 的 Wan VAE在时序卷积内部维护了跨步 feat_cache，流式调用时必须沿用 codec 原生的缓存传递与末尾冲刷（flush）协议。

轻量 decoder 改变质量预算

TAEHV 等轻量级近似自编码器通过大幅缩减通道与层数来换取数倍解码提速与更低显存占用，并针对不同模型的 latent 空间提供专用权重。由于轻量网络属于有损近似，适合交互式实时预览或低延迟草稿生成；最终高清成片导出则可切回原版 VAE。

首帧与稳态指标

  1. 首帧呈现延迟（TTFF）与服务端首块就绪时间： 若以客户端实际呈现首帧为终点，端到端指标应按时间边界定义为： $$\text{TTFF} = t_{\text{客户端首帧呈现}} - t_{\text{约定的请求起点}}$$ 完整关键路径除模型生成外，还可能包含媒体编码/封装、网络传输、客户端解码与播放缓冲等待。若仅统计串行路径上服务端首块就绪时间（不含编码封装与网络/客户端阶段），可写作： $$T_{\text{first-chunk,server}} = T_{\text{TextEnc}} + T_{\text{DiT}}(\text{Chunk 0}) + T_{\text{VAE}}(\text{Chunk 0})$$ 报告中应与第 5 章保持一致，明确 $T_{\text{DiT}}(\text{Chunk 0})$ 是否包含必要的历史 KV commit（clean latent 在末步去噪结束时即已就绪，具体实现可选择在 commit 完成后或与 commit 并行启动首块解码）。无论采用哪种口径，首块生成与首块解码之间都存在严格的数据依赖，流水线重叠无法缩短首块本身的 DiT(Chunk 0) + VAE(Chunk 0) 串行路径；要压低 TTFF，必须靠首块少步求值、预计算条件或更快的解码。

  2. 稳态播放预算（Steady-State Pacing）： 设每个 Chunk 解码后可播放的视频时长为 $\Delta T_{\text{play}}$。当主干去噪与上一块 VAE 解码分布在不同设备或能充分并行重叠时，不发生播放卡顿（underrun）的稳态预算为： $$\max\left( T_{\text{DiT}}(\text{Chunk } k), T_{\text{VAE}}(\text{Chunk } k) \right) \le \Delta T_{\text{play}}$$ 以上表排程为例，每块可播放时长 $\Delta T_{\text{play}}=1.2\text{ s}$（例如单块产出 36 帧、按 30 fps 播放），此时 $T_{\text{DiT}}=T_{\text{VAE}}=1.2\text{ s}$ 恰好踩在不卡顿边界上；反之，若某个模型配置每块仅产出 16 帧、按 24 fps 播放（$\Delta T_{\text{play}}\approx 0.67\text{ s}$），则 $1.2\text{ s}$ 的单块生成或解码耗时就会违反上式并触发播放欠载。 反之，若 DiT 与 VAE 共用同一张已跑满算力/带宽的 GPU，简单把它们放进两个 CUDA Stream 往往只会触发硬件资源争抢，无法真正掩盖解码耗时。因此验证双缓冲流水线时，必须先分别测出单块 $T_{\text{DiT}}$ 与 $T_{\text{VAE}}$ 的独立耗时，再对比串行与双流在完整多块序列上的总 wall time 及 trace 重叠区间。

联合音视频的时间轴

对于同时产出视频与伴生音轨的多模态生成任务，需将两路 codec 解码纳入同一播放时钟（PTS，Presentation Timestamp）对齐管理。RTP 时间戳与跨流同步规范

  • 设视频帧率为 $\text{FPS}$，音频采样率为 $R_{\text{audio}}$（如 32,000 Hz）；
  • 每帧视频对应的平均音频采样点数为： $$S_{\text{audio/frame}} = \frac{R_{\text{audio}}}{\text{FPS}}$$ 当 $R_{\text{audio}} = 32{,}000,\ \text{FPS} = 24$ 时，$S_{\text{audio/frame}} = 1333.\dot{3}$。由于单帧采样点数不是整数，工程上应使用有理数时间基（timebase）或分数累加器计算每个 Chunk 的 PTS，避免按帧向下取整截断为 1333 个样本而导致长视频音画逐渐脱节。

时钟、队列与取消

流式服务在生成端与客户端之间维护有界发送队列。当客户端网络阻塞或消费变慢时，背压（backpressure）应限制在当前会话自己的流控状态内，避免阻塞全局事件循环（详见Omni 配套文档）。收到客户端打断或取消请求时，服务端立即停止调度该会话的后续 chunk，过滤已在途的旧 epoch 输出，并等待已发射的 GPU Kernel 和 DMA 传输到达完成事件后再安全回收缓冲区。

双向整段与 AR 逐块交付

Wan2.2 原生 T2V 入口在全部去噪步结束后才一次性调用 VAE。而 SolarWM 等连续 AR 模型天然支持逐块产出 latent，只需按 codec 的时序上下文要求对齐生成块与解码块的帧索引（并在末尾冲刷残余帧），即可构建边生成、边解码、边推流的端到端管线。

第16章 组合优化与回归验收

单项优化通过以后，系统瓶颈和缓存有效条件往往随之转移：Attention 提速后，QKV/MLP 线性层或布局重排可能上升为主导开销；步数压低到 4 步后，跨步缓存判定与历史 KV 提交的占比显著放大。组合多项技术时，应从一个已验证的基线配置出发，逐项测量增量收益与交叉影响。质量评估方法沿用第 5 章。

先选值得组合的两项

从目标请求的端到端时间线（wall time 分解）中挑选互补候选，并结合第 15 章的 Amdahl 分析估算组合上限：若 PCIe 历史回传已占显著耗时，先按第 13 章优化持久锁页内存与预取；若短算子之间存在密集的 Host 发射空档，则优先融合算子或捕获 CUDA Graph。

两项优化叠加时，即使作用于不同代码层，也可能在底层争用显存容量、PCIe 带宽或共享内存。下表列出四组常见组合的交互焦点与组织方式：

动态复用与静态 Graph 怎样共存

TeaCache 的跳步判定依赖当前步输入特征的动态变化量，而单个静态 CUDA Graph 重放的是固定算子序列。要让两者协同工作，可将轻量 proxy 计算、误差累加与分支决策留在 Graph 外部，同时为“完整执行子图并刷新残差”和“直接加上次缓存残差”分别捕获两张独立 CUDA Graph。每步先原地更新输入与时间步 buffer，再根据判定结果重放对应 Graph，两条路径共享同一输出 buffer 地址。

这种双图分派保留了动态跳步能力，但需要注意 .item() 等将标量拉回 Host 判定的同步开销仍发生在每一步。如果 proxy 评估与同步耗时接近省下的计算时间，或者多分辨率、多 expert 导致需要维护的 Graph 数量过多，则应先在单一固定分辨率下核算显存池与净延迟收益。Graph 显存池复用规则见第 11 章。

对采用独立 clean-refresh（或其他专门历史提交前向）协议的连续 AR 模型，多步去噪的残差缓存与历史 KV 提交必须严格解耦：无论去噪步命中多少次缓存，跨步跳步策略都不能无意跳过必要的历史提交路径（是否需要独立 refresh 前向由模型上下文协议决定，见第 12 章）。

量化与缓存先固定表示，再校准策略

将权重量化/激活量化与跨步特征缓存组合时，应先锁定通过质量验收的量化配置，再在量化模型上重新校准缓存阈值 $\tau$。这是因为低精度算子会微调中间特征分布与 proxy 相对变化量，直接沿用全精度模型标定的阈值可能改变跳步序列；同时，被缓存并跨步复用的残差本身已带有量化舍入误差。

实验对比时，建议同时记录“沿用参考命中的固定跳步序列”与“在量化路径上重新动态判定”的画面差异，从而分清质量波动究竟来自算子数值误差还是跳步决策偏移。

Offload 保持地址，事件保护数据内容

CUDA Graph 要求重放期间所有被读取的参数与缓冲地址固定不变。若采用按需卸载再动态创建参数张量的普通 Offload，每次搬回 GPU 都会改变底层 data_ptr，直接破坏已捕获的 Graph。解决方案是在显存中预留固定地址的 staging buffer：搬运流（copy stream）先将下一层或下一阶段所需的权重/KV 异步拷入 staging buffer 并记录 ready 事件；计算流等待 ready 事件后重放读取该固定地址的 Graph，并在重放结束后记录 consumed 事件；下一次覆写同一 staging 槽位前必须等待 consumed 事件完成。

采用双缓冲（ping-pong staging buffers）可以在重放当前层 Graph 的同时预取下一层数据，但新增的常驻缓冲区需与 Graph 私有池、激活峰值一并纳入显存账本。

Ulysses 压缩通信时，scale 也参与转置

第 14 章的 Ulysses All-to-All 将 [N/P, H, d]（切序列、全 head）转置为 [N, H/P, d]（全序列、切 head）。若将跨卡交换的 Q/K/V 压缩为 INT8 或 FP8 以节省通信带宽，量化缩放因子（scale）必须与对应的数据分片同步完成跨 rank 转置。

稳妥的实现顺序是：先按目标 rank 重排打包待发送分片，在每个发送分片内部按约定粒度（如 per-token 或 per-head-block）计算 scale，再将量化载荷与 scale 一并发送，接收端解包反量化后恢复目标布局。

多卡与图执行的组合核验清单

将分布式通信、Offload 与低精度图执行集成到一起时，建议通过以下三项自包含契约测试逐一门禁：

  1. All-to-All 量化转置核验：先用可唯一标识位置与 head 编号的索引张量验证跨 rank 转置与逆转置的坐标准确性，再对比 BF16 与 INT8/FP8 打包通信（含 scale 同步转置）的还原误差及端到端通信耗时。
  2. Offload + CUDA Graph 驻留保护核验：在跨 Stream 异步拷贝与 Graph 重放循环中校验 staging 槽位指针（data_ptr）全程零重分配，并在重放前向输出缓冲注入 NaN 毒化值，验证事件互锁下每次重放均完整覆写出正确结果。
  3. 低精度算子真实分发核验：在目标硬件（如 SM90 / SM120）上通过 profiler 确认 torch._scaled_mm 或低精度 Attention 确实命中硬件 Tensor Core 指令，并将前后量化转换、布局重排计入总耗时。

用 2×2 对照测增量与交互

评估两项候选优化 A 与 B 的组合效果时，按标准 $2\times2$ 消融矩阵采集四组配置（reference $T_{00}$、仅开 A 的 $T_{10}$、仅开 B 的 $T_{01}$、同时开启 A+B 的 $T_{11}$）：

配置 方法 A 方法 B 同一边界下的 wall time
reference 关 关 $T_{00}$
A 开 关 $T_{10}$
B 关 开 $T_{01}$
A+B 开 开 $T_{11}$

四组配置固定同一模型权重、输入提示词、随机种子、采样步数与计时边界，各自独立重置状态并完成预热，穿插 A/B/A 基线复测监控环境漂移。在已开启 B 的基础上叠加 A 的边际加速比为 $T_{01}/T_{11}$；两项优化的交互项定义为：

$$I=T_{11}-T_{10}-T_{01}+T_{00}$$

当 $I<0$ 时，说明两项优化存在协同增益（例如量化缩小了载荷，使预取更容易被计算完全掩盖）；当 $I>0$ 时，则表明两者消减了同一部分耗时（如少步蒸馏与跨步缓存都在减少主干块执行次数）或引入了额外的格式转换开销。

  2. ar_microbench_sm90.json 保存了 50 层 AR 视频规模（56 头、128 维、每块 1200 token）下活跃窗口（5 块 6,000 token，Gather 输出 8.60 GB BF16）与静态分页池（7 块 8,512 槽位，含页尾 padding 与 FP8 scales）的容量分解，以及连续块 torch.cat 与 Python 侧 Paged BF16 / Paged FP8 逐页物化路径的 50 层 Gather 汇总耗时（summary_only: true，无逐次热样本或随包生成脚本）。

三份数据文件均可通过 python3 -B examples/review_public_evidence.py（配合 --input 参数）离线核验。有效搬运带宽定义为单轮净载荷字节数除以包含提交与同步在内的 Host wall time，用于衡量应用层实际可得的传输吞吐。

阅读实验数据时，按各章对应的工程问题对号入座：第 8 章对比 Attention 算子后端，第 11 章衡量小算子栈的发射开销与 Graph 摊销回本点，第 12 章对比滑动窗口状态容器与分页物化成本，第 13 章评估锁页内存对 PCIe 搬运的影响。
